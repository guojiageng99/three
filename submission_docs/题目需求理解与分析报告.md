# 题目需求理解与分析报告

## 一、题目背景与目标理解

本项目选择复刻论文 *Generative Agents: Interactive Simulacra of Human Behavior* 的核心思想，并结合课程作业的演示型要求，将论文中的生成式智能体机制压缩为一个可运行、可展示、可讲解的最小完整机制系统。

论文的核心并不是“做一个会走路的 NPC 地图”，而是构建一个能够在开放环境中持续感知、记忆、规划、行动、互动并形成反思的智能体系统。其关键价值在于：

1. 智能体的行为不是完全脚本化的，而是由当前环境和过往记忆共同驱动。
2. 智能体之间的交互会产生新的社会关系与传播链条。
3. 长期行为不是简单状态机，而是通过记忆检索与高层反思来影响后续决策。

对于课程作业而言，题目的真实考查点不是“是否论文级完整复现”，而是以下几个方面：

- 是否理解论文中的核心机制，而不是只复刻表面 UI。
- 是否能够将论文方法压缩成一个工程上可运行的 demo。
- 是否能够把系统设计、关键模块、数据流和技术取舍讲清楚。
- 是否能够形成代码、报告、PPT 和视频讲解的完整交付链。

因此，本项目的总体目标被定义为：

`构建一个 Smallville 风格的课程演示系统，用 3 个以上 NPC 展示“感知 -> 记忆检索 -> 计划 -> 行动/对话 -> 记忆更新 -> 反思”的闭环。`

## 二、作业要求拆解

结合课程模板与提交形式，本项目的需求可以拆成五类。

### 2.1 代码可运行需求

- 系统必须能够在本地运行。
- 前后端需要形成完整的状态流，而不是静态页面。
- 至少要支持地图、时间推进、角色状态、日志与交互显示。

### 2.2 机制复现需求

- 需要体现 NPC 具有独立 profile。
- 需要体现日计划，而非纯随机行动。
- 需要体现记忆记录与检索。
- 需要体现至少一次信息传播或社交互动链。
- 需要体现高层反思的生成。

### 2.3 可演示需求

- 需要可视化界面，便于录制讲解视频。
- 需要能够解释某个 NPC 当前为什么这样行动。
- 需要有足够直观的事件链，便于课堂展示。

### 2.4 报告支撑需求

- 需求分析报告需要说明为什么选择该论文、核心问题是什么、复刻范围如何界定。
- 技术方案报告需要说明架构、数据流、模块设计、关键创新点与简化策略。
- PPT 需要从项目背景、论文机制、系统架构、实现细节、演示流程、结果分析多个角度展开。

### 2.5 时间约束需求

提交时间是 `2026-06-13`，项目必须围绕短周期交付优化：

- 优先完成最小完整链路
- 优先保证可演示性
- 避免陷入论文级高复杂度细节

## 三、需求场景分析

本项目的核心场景不是通用多智能体平台，而是一个“可控、可观察、可讲解”的小镇社交仿真场景。

系统中的典型场景包括：

1. 某个 NPC 根据自己的计划在固定时间前往某地点。
2. NPC 到达后根据当前地点、当前时间、附近人物和已有记忆决定当前动作。
3. 两个 NPC 相遇时，可能发生对话与信息传播。
4. 对话会形成新记忆，并影响后续行为。
5. 当某一事件在多个 NPC 中传播后，会形成更高层的社会性反思。

这些场景共同说明：系统的目标不是高自由度开放世界，而是用最小世界支撑最关键的认知闭环。

## 四、核心问题识别

从需求角度看，本项目需要解决以下四个核心问题。

### 4.1 如何避免沦为“纯脚本 NPC”

如果角色行为完全固定，那么系统只能算剧情演示，不足以体现 generative agents 的本质。因此必须引入：

- profile
- plan
- memory retrieval
- dialogue generation
- reflection

### 4.2 如何在短时间内控制实现复杂度

论文中的完整系统包含更大规模角色、更长时间仿真、更复杂检索与社会传播机制。课程作业时间不允许全量复现，因此必须做合理简化：

- 角色数从论文级多角色缩减为 3 个
- 地图缩减为 4 个关键地点
- 检索算法采用轻量打分策略
- LLM 调用采用兼容接口并提供 fallback

### 4.3 如何确保演示效果清晰

仅有后端机制不足以支撑课堂讲解，因此系统必须暴露：

- 当前时间
- 当前计划
- 当前动作
- 最近记忆
- 检索到的记忆
- 反思结果
- 事件日志

### 4.4 如何兼顾稳定性与“像大模型系统”

如果所有行为都强依赖在线模型，演示稳定性会下降；如果完全不用模型，又失去课程特色。因此系统采用：

- `LLM 优先`
- `规则模板兜底`

这种双模式设计能兼顾稳定演示与大模型应用价值。

## 五、范围界定

### 5.1 本项目纳入范围

- 2D 小镇地图展示
- 3 个 NPC 的差异化 profile
- 世界时间推进
- 固定地点之间的移动
- 记忆记录与检索
- 计划生成
- 行动/对话生成
- 信息传播链
- 反思生成
- 可视化解释面板

### 5.2 本项目不纳入范围

- 论文级 20+ NPC 规模
- 长周期自治模拟
- 复杂向量数据库
- 多模态输入
- 强化学习
- 论文原实验的严格指标复现

这种范围控制是项目按时交付的前提。

## 六、需求优先级分析

### 6.1 必须完成

- 地图与时间推进
- NPC 计划和移动
- 记忆记录与检索
- 至少一条社交传播链
- 反思形成
- 前端解释面板
- 代码可运行

### 6.2 应当完成

- 在线 LLM 兼容调用
- fallback 稳定机制
- 更清晰的推理上下文展示
- 更完整的文档与 README

### 6.3 可选增强

- 更多 NPC
- 更丰富的地点
- 更复杂的事件链
- 更细粒度的计划生成

## 七、验收标准

从课程作业演示的角度，系统验收标准应定义为：

1. 系统可以本地启动，并能展示小镇地图与多个 NPC。
2. NPC 会随着时间推进切换地点与动作。
3. 系统能显示当前计划、最近记忆、检索到的记忆和反思。
4. 至少存在一条完整的信息传播链，例如 `Alice -> Bob -> Carol`。
5. 系统可以清晰解释 NPC 的当前行为依据。
6. 系统具备代码、报告、PPT 和视频讲解所需的素材基础。

## 八、结论

本项目的需求本质上是一个“受时间约束的论文机制压缩复现”问题。其重点不在于论文级规模，而在于把最关键的认知闭环、社交传播闭环和可视化解释闭环落成一个可运行工程。

因此，当前项目选择的目标是合理的：

`做一个适合课堂展示的最小完整机制 Generative Agents 复刻系统，而不是做一个高复杂度但无法按时交付的全量论文复现。`
